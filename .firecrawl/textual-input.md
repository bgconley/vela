### Restricting Input [¶](https://textual.textualize.io/widgets/input/\#restricting-input "Permanent link")

You can limit input to particular characters by supplying the `restrict` parameter, which should be a regular expression.
The `Input` widget will prevent the addition of any characters that would cause the regex to no longer match.
For instance, if you wanted to limit characters to binary you could set `restrict=r"[01]*"`.

Note

The `restrict` regular expression is applied to the full value and not just to the new character.

### Maximum Length [¶](https://textual.textualize.io/widgets/input/\#maximum-length "Permanent link")

You can limit the length of the input by setting `max_length` to a value greater than zero.
This will prevent the user from typing any more characters when the maximum has been reached.

### Validating Input [¶](https://textual.textualize.io/widgets/input/\#validating-input "Permanent link")

You can supply one or more _[validators](https://textual.textualize.io/api/validation/#textual.validation.Validator "Validator")_ to the `Input` widget to validate the value.

All the supplied validators will run when the value changes, the `Input` is submitted, or focus moves _out_ of the `Input`.
The values `"changed"`, `"submitted"`, and `"blur"`, can be passed as an iterable to the `Input` parameter `validate_on` to request that validation occur only on the respective messages.
(See [`InputValidationOn`](https://textual.textualize.io/api/types/#textual.types.InputValidationOn) and [`Input.validate_on`](https://textual.textualize.io/widgets/input/#textual.widgets._input.Input.validate_on).)
For example, the code below creates an `Input` widget that only gets validated when the value is submitted explicitly:

```
input = Input(validate_on=["submitted"])
```

Validation is considered to have failed if _any_ of the validators fail.

You can check whether the validation succeeded or failed inside an [Input.Changed](https://textual.textualize.io/widgets/input/#textual.widgets._input.Input.Changed), [Input.Submitted](https://textual.textualize.io/widgets/input/#textual.widgets._input.Input.Submitted), or [Input.Blurred](https://textual.textualize.io/widgets/input/#textual.widgets._input.Input.Blurred) handler by looking at the `validation_result` attribute on these events.

In the example below, we show how to combine multiple validators and update the UI to tell the user
why validation failed.
Click the tabs to see the output for validation failures and successes.

[input\_validation.py](https://textual.textualize.io/widgets/input/#__tabbed_3_1)[Validation Failure](https://textual.textualize.io/widgets/input/#__tabbed_3_2)[Validation Success](https://textual.textualize.io/widgets/input/#__tabbed_3_3)

```
from textual import on
from textual.app import App, ComposeResult
from textual.validation import Function, Number, ValidationResult, Validator
from textual.widgets import Input, Label, Pretty

class InputApp(App):
    Textual offers default styling for the -invalid CSS class (a red border), which is automatically applied to Input when validation fails. We can also provide custom styling for the -valid class, as seen here. In this case, we add a green border around the Input to indicate successful validation.

    CSS = """
    Input.-valid {
        border: tall $success 60%;
    }
    Input.-valid:focus {
        border: tall $success;
    }
    Input {
        margin: 1 1;
    }
    Label {
        margin: 1 2;
    }
    Pretty {
        margin: 1 2;
    }
    """

    def compose(self) -> ComposeResult:
        yield Label("Enter an even number between 1 and 100 that is also a palindrome.")
        yield Input(
            placeholder="Enter a number...",
            validators=[\
                Number(minimum=1, maximum=100),  Number is a built-in Validator. It checks that the value in the Input is a valid number, and optionally can check that it falls within a range.\
\
                Function(is_even, "Value is not even."),  Function lets you quickly define custom validation constraints. In this case, we check the value in the Input is even.\
\
                Palindrome(),  Palindrome is a custom Validator defined below.\
\
            ],
        )
        yield Pretty([])

    @on(Input.Changed)
    def show_invalid_reasons(self, event: Input.Changed) -> None:
        # Updating the UI to show the reasons why validation failed
        if not event.validation_result.is_valid:  The Input.Changed event has a validation_result attribute which contains information about the validation that occurred when the value changed.

            self.query_one(Pretty).update(event.validation_result.failure_descriptions)
        else:
            self.query_one(Pretty).update([])

def is_even(value: str) -> bool:
    try:
        return int(value) % 2 == 0
    except ValueError:
        return False

# A custom validator
class Palindrome(Validator):  Here's how we can implement a custom validator which checks if a string is a palindrome. Note how the description passed into self.failure corresponds to the message seen on UI.

    def validate(self, value: str) -> ValidationResult:
        """Check a string is equal to its reverse."""
        if self.is_palindrome(value):
            return self.success()
        else:
            return self.failure("That's not a palindrome :/")

    @staticmethod
    def is_palindrome(value: str) -> bool:
        return value == value[::-1]

app = InputApp()

if __name__ == "__main__":
    app.run()
```

as seen for `Palindrome` in the example above.

#### Validate Empty [¶](https://textual.textualize.io/widgets/input/\#validate-empty "Permanent link")

If you set `valid_empty=True` then empty values will bypass any validators, and empty values will be considered valid.

## validate [¶](https://textual.textualize.io/widgets/input/\#textual.widgets._input.Input.validate "Permanent link")

```
validate(value)
```

Run all the validators associated with this Input on the supplied value.

Runs all validators, combines the result into one. If any of the validators
failed, the combined result will be a failure. If no validators are present,
None will be returned. This also sets the `-invalid` CSS class on the Input
if the validation fails, and sets the `-valid` CSS class on the Input if
the validation succeeds.

**Returns:**

| Type | Description |
| --- | --- |
| `ValidationResult | None` | A ValidationResult indicating whether _all_ validators succeeded or not.<br>That is, if _any_ validator fails, the result will be an unsuccessful<br>validation. |
